## 指示①：設計レビューを頼む（演習3-1／ファイルは変えさせない）

【役割】データベース設計を教える先生として。
【目的】docs/schema.sql を読んで、気になる点を「提案」として3つまで挙げてください。
【制約】
- ファイルは一切変更しないこと
- 観点は「正規形（同じ値の重複）」「キー（1行を見分けられるか）」「型（値に合っているか）」の3つ
- 提案ごとに「なぜそう思うか」を初学者向けに1〜2文で
【完了条件】
- 番号つきで提案が最大3つ並んでいる
- 最後に「変更したファイル：なし」と書いてある

→ 採用するかどうかは自分で決める。ワークシートp.2の表に「採用／不採用＋理由」を書く。
→ 採用する場合も、schema.sql を直すのは自分。Azure 側も作り直して反映する。

## 指示②：最小アプリを作る（演習3-2）

【役割】初学者に付き添うWeb開発者として。
【目的】docs/schema.sql の「＿＿＿」テーブルのサンプルデータ5件を、表で一覧表示する index.html を作ってください。
【制約】
- データは data/sample-data.js に JavaScript の変数として書き、index.html から <script src> で読み込む
- 表の見出しは schema.sql の列名と同じにする
- Node.js・npm・サーバー・外部ライブラリは使わない（ダブルクリックで開いて動くこと）
- docs/ の中のファイルは変更しない
【完了条件】
- index.html をダブルクリックすると、5件のデータが表で見える
- 最後に「変更したファイル：」として作ったファイルの一覧がある

## 指示③：説明させる（演習3-3）

index.html と data/sample-data.js を、上から順に、初学者向けに説明してください。
1つのまとまりごとに「ここは何をしているか」を1行で。

→ 説明を読んでも分からない行に、自分で印（// ？）をつける。それが次回の質問になります。
